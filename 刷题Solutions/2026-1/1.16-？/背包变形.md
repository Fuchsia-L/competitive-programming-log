# ACM 练习笔记 (2026-01-16)

## [001] AtCoder - Robot Customize (DP / 01背包变体)
* **题目大意**: 
  有 N 个零件，每个零件有重量 W、头部幸福度 H 和身体幸福度 B。要求把所有零件分别安装在头部或身体，且必须满足：头部总重 <= 身体总重。求最大总幸福度。
  约束：N <= 500, Wi <= 500, Hi/Bi <= 10^9。

* **核心逻辑**:
  1. 条件转化 (核心突破口)：
     令头部重量为 Wh，身体重量为 Wb，所有零件总重为 S (S = sum(Wi))。
     由于所有零件必须用上，所以 Wh + Wb = S，即 Wb = S - Wh。
     题目要求 Wh <= Wb，代入得 Wh <= S - Wh，整理得：Wh <= S/2。
     这说明只要头部重量不超过总重的一半，约束就永远成立。

  2. 模型转化 (增益法背包)：
     先假设所有零件都装在“身体”上，初始总幸福度为 sum(Bi)。
     现在考虑将零件 i 移到“头部”：
     - 代价 (重量)：增加 Wi。
     - 收益 (价值)：Hi - Bi (得到了头部的幸福，失去了身体的幸福)。
     此时问题变成：在容量为 S/2 的背包里，放入价值为 (Hi - Bi)、重量为 Wi 的物品，求最大收益。

  3. 状态转移：
     dp[j] 表示头部重量为 j 时的最大幸福增益。
     初始化：dp[0] = 0, 其余为负无穷 (表示该重量尚未凑出)。
     转移方程：dp[j] = max(dp[j], dp[j - Wi] + (Hi - Bi)) (逆序遍历 j)。

* **总结/关键点**:
  - 动态约束静态化：当两个集合的总和固定时，A <= B 类约束通常可以转化成 A <= Sum/2。
  - 负增益处理：Hi - Bi 可能是负数。但在 01 背包中，如果增益为负，dp 转移时 max 操作会自动放弃该选项，除非它是凑成某个重量的必经之路。
  - 数据类型：幸福值总和超过 10^14，代码中必须全程使用 long long。
  - 时间复杂度：O(N * S)，其中 S = N * max(Wi) = 250,000。总计算量约 1.25 * 10^8，在 C++ 2秒时限内可以通过。

💡 **[小贴士/赛前建议]**
* 遇到这种“二选一”且有整体比例限制的题目，第一反应应该是“固定总和”。
* 别被题目里的“机器人”或者“部件”这种表象迷惑，剥离出 Weight 和 Value 的关系就是标准的背包。
