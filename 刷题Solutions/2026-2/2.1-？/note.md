## [Codeforces] [Beautiful Subsequences - 1, 2...2, 3](https://codeforces.com/contest/2069/problem/C) (DP / 组合数学 / 线性优化)

* **题目大意**: 
  给定一个长度为 $N$ 且只包含 1, 2, 3 的数组。求有多少个子序列满足：开头是 1，结尾是 3，中间至少包含一个 2。结果对 998244353 取模。

* **核心逻辑**:
  1. **暴力误区 ($O(N^2)$)**: 
     每遇到一个 3，就回头遍历前面所有的 1，计算它们之间夹了多少个 2。虽然逻辑直观，但两层循环会导致 TLE。
  
  2. **线性优化 ($O(N)$)**: 
     转变思路，维护“当前所有 1 的潜能状态”向后遍历。
     - 维护 `cnt1`: 记录当前遇到的 1 的总个数。
     - 维护 `weight`: 记录当前所有 1 的“组合潜能”总和。
  
  3. **状态转移方程**:
     - **遇到 1**: 
       新增加一个起点。该起点的初始潜能为 1（代表 $2^0$，即后面还没有 2 的情况）。
       `weight = (weight + 1) % MOD;`
       `cnt1++;`
     - **遇到 2**: 
       这个 2 对前面**所有的** 1 都有效。对于每个 1，方案数从 $2^k$ 变为 $2^{k+1}$（选或不选这个 2）。
       `weight = (weight * 2) % MOD;`
     - **遇到 3**: 
       收网计算。当前 `weight` 包含了所有 1 到这里的所有组合（包括中间没有 2 的情况）。
       题目要求中间至少有一个 2，所以要减去“空集”情况（即 `cnt1` 个）。
       `current_ans = (weight - cnt1 + MOD) % MOD;`
       `total_ans = (total_ans + current_ans) % MOD;`

* **总结/关键点**:
  1. **思维降维**: 遇到“找前面有多少满足条件”的题，优先考虑能否维护一个全局变量带着走，将 $O(N^2)$ 降为 $O(N)$。
  2. **累加更新**: 最终答案 `ans` 是累加过程，不要写成覆盖（`=`），要写成累加（`+=`）。
  3. **取模陷阱 (重点!)**: 
     C++ 中 `(a - b) % p` 当 `a < b` 时结果为负数！
     **错误写法**: `ans = (weight - cnt1) % MOD;`
     **正确写法**: `ans = (weight - cnt1 + MOD) % MOD;` 
     这一步必须手动加 `MOD` 把结果抬回正数区间，否则会导致 WA。

## [Codeforces/Kattis] [Karamell - 糖果分配](题目链接) (DP / 构造 / 贪心模拟)

* **题目大意**: 
  有 $N$ 袋糖果，每袋数量不同。两个人（Alice 和 Bob）分糖，规则是固定的：按给定顺序处理袋子，当前谁糖少就给谁（一样多给 Alice）。
  **目标**：重新排列袋子的顺序，使得最后两人分到的糖果总数相等。

* **核心逻辑**:
  这是一道“披着贪心皮的背包题”。解法分两步：**定结果** + **凑过程**。
  
  1. **可行性判定 (0/1 背包)**:
     - 首先，如果糖果总和 $Sum$ 是奇数，直接输出 `-1`。
     - 目标是将糖果分成两堆，每堆和为 $Sum/2$。
     - 使用 **0/1 背包 DP**。为了能输出方案，DP 数组需要记录路径：
       `dp[j] = {上一个重量, 当前物品ID}` (使用 `pair` 记录前驱状态)。
     - 如果 `dp[Sum/2]` 无法到达，输出 `-1`。
  
  2. **构造序列 (双队列模拟)**:
     - 根据 DP 的回溯结果，将袋子分为 **Set A (Alice 预定)** 和 **Set B (Bob 预定)**，放入两个队列 `qA` 和 `qB`。
     - **“欺骗”贪心规则**:
       - 模拟发糖过程，维护 `sumA` 和 `sumB`。
       - 规则说“给少的那个”：
         - 如果 `sumA <= sumB` (Alice 需要糖): 强制从 `qA` 拿出一袋给 Alice。
         - 如果 `sumA > sumB` (Bob 需要糖): 强制从 `qB` 拿出一袋给 Bob。
  
  3. **数学保证**:
     - 只要 $Sum(A) = Sum(B)$，上述模拟过程**绝对不会崩**（不会出现“Alice 需要糖但 `qA` 空了”的情况）。这是由总和相等这一性质保证的。

* **总结/关键点**:
  1. **DP 路径还原**: 
     做背包问题如果需要输出具体方案，不要只存 `bool` 或 `int`，可以用 `pair<int, int> path[w]` 记录 `{来源状态, 物品下标}`，方便倒推回溯。
  2. **逆向思维 (Constructive Algorithms)**:
     面对强制的贪心规则，不要试图去推导复杂的排序不等式。先确定最终归属（谁拿哪些），再顺着规则“喂”数据。
  3. **代码技巧**:
     利用两个 `std::queue` 来管理预分配的集合，代码逻辑会非常清晰，避免了复杂的指针操作。
