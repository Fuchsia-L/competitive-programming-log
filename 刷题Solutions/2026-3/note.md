# ACM 练习笔记 (2026-03-06)

## [001] [P2543 - 奇怪的字符串](https://www.luogu.com.cn/problem/P2543) (DP / 最长公共子序列)

* **题目大意**: 给定两个只含 0 和 1 的字符串 X 和 Y（长度最大 9999），求它们的最长公共子序列 (LCS) 的长度。

* **核心逻辑**:
  1. **状态定义**: `dp[i][j]` = `a` 的前 `i` 个字符与 `b` 的前 `j` 个字符的 LCS 长度。
  2. **转移方程**:
     - `a[i] == b[j]`：配对，`dp[i][j] = dp[i-1][j-1] + 1`
     - `a[i] != b[j]`：丢一个取较大，`dp[i][j] = max(dp[i-1][j], dp[i][j-1])`
  3. **边界**: `dp[0][...] = dp[...][0] = 0`。
  4. **滚动数组**: `dp[i]` 只依赖上一行和当前行，开 `dp[2][10009]` 用 `cur/pre` 交替即可。
  5. **遍历方向**: `j` 必须正序，因为 `dp[cur][j]` 依赖 `dp[cur][j-1]`（当前行左边已算好的值）。

* **总结/关键点**:
  1. 全局数组超过几十 MB 就要用滚动数组优化空间。`int dp[10099][10099]` 约 389 MB，直接崩溃。
  2. 不匹配时必须同时考虑"丢 `a[i]`"和"丢 `b[j]`"两种情况，取 max，不能只写一半。
  3. 滚动数组的内层循环方向由依赖关系决定：需要当前行左边的值就正序，需要当前行右边的值就倒序。

## [002] [P1439 - 两个排列的最长公共子序列](https://www.luogu.com.cn/problem/P1439) (LCS → LIS)

* **题目大意**: 给出 1~n 的两个排列 P1 和 P2，求最长公共子序列长度。n 最大 1e5。

* **核心思路**: 利用排列的性质，将 LCS 转化为 LIS，复杂度从 O(n²) 降到 O(n log n)。
  1. **建立位置映射**: 记录 P1 中每个值的位置 `pos[P1[i]] = i`。
  2. **替换 P2**: 将 P2 的每个值替换为它在 P1 中的位置，得到新序列 B。
  3. **求 B 的 LIS**: B 的最长递增子序列长度 = 原两个排列的 LCS 长度。
  4. **LIS 用贪心+二分**: 维护数组 `d`，`d[k]` 表示长度为 k 的递增子序列的最小末尾。对每个元素二分查找插入位置，若在末尾则长度 +1，否则替换使末尾更优。

* **踩坑记录**:
  1. **映射方向搞反**: 错误写法 `b[i] = P1[P2[i]]`（用 P2 的值去索引 P1 的值），这只是值到值的映射，不是位置映射。正确写法是先建 `pos[P1[i]] = i`，再 `b[i] = pos[P2[i]]`，把 P2 的值映射为它在 P1 中的**位置**。
  2. **LIS 长度计算错误**: 用计数数组 `num` 统计每个位置被替换的次数再取 max，完全偏离了 LIS 的逻辑。正确做法是直接维护 `d` 数组的有效长度——每次新元素追加到末尾时长度 +1，替换时长度不变。

* **超时方法**: 标准 O(n²) 的 LCS DP（滚动数组优化空间），对 n=1e5 无法通过。排列的 LCS 必须转 LIS。
