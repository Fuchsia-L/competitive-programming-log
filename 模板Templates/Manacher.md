# 算法笔记：Manacher（最长回文半径，O(n)）

## 1. 问题与朴素解法

求字符串 s 中以**每个位置**为中心的最长回文半径（或最长回文子串）。

朴素中心扩展：每个位置都从半径 0 开始向两边扩，最坏 O(n²)。Manacher 把它降到 **O(n)**。

---

## 2. 蘑菇喻：直觉

> 每个位置头顶都有一朵蘑菇——蘑菇盖 = 以它为中心的最大回文范围。

朴素法是给每朵蘑菇**从零开始单独测量**。Manacher 利用一个事实：

**已知最大蘑菇内部是镜像对称的**——所以右半部分某位置头顶的蘑菇大小，跟左半部分对称位置的蘑菇相同（只要不超出大蘑菇覆盖范围）。

把已经测好的左半部分的蘑菇大小**直接抄到右半部分对应位置**，省去重测。

---

## 3. 算法

维护：
- `c`: 当前"已知最右回文"的中心
- `r`: 该回文的右端 `r = c + p[c]`
- `p[]`: 半径数组

来到新位置 `i`：

### Step 1 — 保底（抄镜像）

若 `i < r`（在大蘑菇覆盖范围内），找镜像 `i' = 2c - i`：

```
p[i] = min(p[i'], r - i)
```

- `p[i']`：镜像位置已经算好的蘑菇半径
- `r - i`：不能超出大蘑菇右端边界（外面没保证镜像）

为什么取 min：
- `p[i']` 完全在大蘑菇里 → 镜像准确，直接用 `p[i']`
- `p[i']` 伸出大蘑菇左边界 → i 处只能保证到 r，外面要重新查

### Step 2 — 继续扩展

```cpp
while (t[i - p[i] - 1] == t[i + p[i] + 1]) p[i]++;
```

只对保底之外的部分**真正比对**。

### Step 3 — 推进最右

```cpp
if (i + p[i] > r) { c = i; r = i + p[i]; }
```

---

## 4. 为什么是 O(n)（关键 amortized 论证）

- "保底"是 O(1) 抄数组——白嫖，不算工作量
- 真正花时间的是 Step 2 的扩展。**每扩成功一格，`r` 严格右移一格**
- `r` 从 0 单调增到 ≤ n，最多移 n 次
- **所有位置加起来，"真扩"的总次数 ≤ n**

朴素法浪费在"每个中心都从 0 开始扩"；Manacher 让每次"真扩"都推动 `r` 前进，无重复。

---

## 5. 实现技巧

### 5.1 `#` 分隔符：奇偶统一

回文有奇有偶（`aba` 长度 3 中心是字符；`abba` 长度 4 中心在两字符之间），直接处理要写两份代码。

把 `s = "abba"` 改造成 `t = "#a#b#b#a#"`，**所有回文都变成奇数长度**：

| 原串回文 | 处理串里中心 |
|---|---|
| `aba`（奇）| 中心是 `b` |
| `abba`（偶）| 中心是中间那个 `#` |

只用一个数组 `p[]` 处理所有情况。

**`p[i]` 的妙处**：在新串 t 里以 t[i] 为中心的最长回文**半径**，**恰好等于**原串里该中心的最长回文**长度**。直接拿来用，不用换算。

### 5.2 哨兵：免边界判断

加 `^` 在最左、`$` 在最右：

```
t = '^' + '#' + s[0] + '#' + s[1] + ... + '#' + '$'
```

扩展时 `t[i-p[i]-1]` 和 `t[i+p[i]+1]` 永远在 t 范围内（`^ != $ != 任何内部字符`），自动失败退出，不需要 `if (l >= 0 && r < n)`。

要求：`^ $ #` 不出现在原串。担心的话用不可打印字符（`\1` `\2` `\3`）。

### 5.3 数组要开够

处理串 t 长度 ≈ `2|s| + 3`。p 数组按这个量算。

P3805 上 `|s| ≤ 1.1×10^7`，p 至少 `2.2×10^7`。**开小了写越界 = UB**，可能伪装成 TLE/RE/段错误。

## 6. 踩坑清单（血泪）

> 写第一遍时全部都踩了一遍，记下来下次别再栽。

### 坑 1：暴力中心扩展是 O(n²)

写完发现 TLE，以为是常数问题——不，是算法本身就 O(n²)。Manacher 是必要的。

### 坑 2：p 数组开小

`int p[12000]` 对 P3805 完全不够，越界写 → UB → 可能死循环伪装成 TLE。

### 坑 3：fast IO 没开

`|s|` 上 10^6/10^7 时，**`cin/cout` 默认与 stdio 同步会 TLE**——Manacher 主循环 O(n)，IO 反而是瓶颈。

```cpp
ios::sync_with_stdio(false);
cin.tie(0);
```

或者直接 `scanf("%s", buf)`。

### 坑 4：构造 t 用 `t = t + ...`

```cpp
t = t + ch + "#";   // 错！每次复制整个 t，O(n²)
```

正确：`t += ch; t += '#';`（amortized O(1) per append）。

### 坑 5：`char + "x"` 是指针偏移，不是字符串拼接 ★ 最坑 ★

```cpp
t += s[i] + "#";   // 错！char + const char* = 指针 + 整数偏移
```

`s[i]` 是 char、`"#"` 是 const char*。`char + const char*` 在 C++ 里是**指针算术**——把 `"#"` 这个地址往后偏 `s[i]` 的 ASCII 值那么多字节，得到一个**随机内存地址**。然后 `string += (随机指针)` 会从那读 C 字符串直到遇 `\0`，把一坨垃圾拼到 t 里。

**一般规则**：`+` 链式拼接，**那一步运算的两边必须有一个是 `std::string`**。`char` 和 `const char*` 自己玩 `+` 永远是数字/指针运算。

修法（任选）：
```cpp
t += s[i]; t += '#';                  // 拆两步
t += string(1, s[i]) + '#';           // 强制变 string
t.push_back(s[i]); t.push_back('#');  // 用 push_back
```

### 坑 6：`'@' + '#'` / `"@" + "#"` 同款指针/数字陷阱

```cpp
"@" + "#"   // 错！两个 const char* 不能相加
'@' + '#'   // 错！char + char = int 加法 (= 99)
```

要把 `@` 和 `#` 拼到一起？**直接写 `"@#"`**——双引号里多塞几个字符就是一个完整字符串字面量。

### 坑 7：调试 `cout` 没删提交

赛后练习时无所谓，比赛/OJ 提交记得删调试输出，否则 WA。
