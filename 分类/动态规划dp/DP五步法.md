# DP 五步法

> 解决"看不出是 DP / 知道是 DP 但写不出 / 写出来不会初始化"三大关卡。

## 关卡 1：认出是 DP

看到这几个**组合信号**多半是 DP：

- **最大/最小/计数**（"最少距离"、"多少种方案"）
- **做一系列决策**（每个元素"选/不选"、每步"走左/走右"）
- **可以按顺序处理**（从左到右、从上到下）
- **没有贪心的"局部最优 = 全局最优"性质**（想出贪心反例 → 换 DP）
- **数据范围在 n² 或 n³ 区间**（n ≤ 5000、n ≤ 500）

CF 1525D Armchairs 例子：最小距离 ✓、每个人匹配哪把椅子是决策 ✓、不交叉保证可以顺序处理 ✓、n ≤ 5000 ✓。**四个信号齐了**。

## 关卡 2：状态设计

记住三个最常用的 DP 模板，90% 的题都是它们的变种：

| 模板 | 状态 | 适用 |
|---|---|---|
| **前缀型** | `dp[i] = 前 i 个的答案` | 一维序列、每步决策独立 |
| **双序列型** | `dp[i][j] = A 前 i 个 + B 前 j 个的答案` | 两个数组匹配、LCS 风格 |
| **区间型** | `dp[l][r] = 区间 [l, r] 的答案` | 分治/合并、回文、矩阵链 |

**状态设计口诀**：

> 状态要能**回答一个完整的子问题**，不能只记一半。

- ❌ "dp[i] = 第 i 个人走了多远" —— 不完整，没说第 i 个人配哪把椅子
- ✅ "dp[i][j] = 前 i 个人都安顿到前 j 把椅子的最小总距离" —— 完整

## 关卡 3：初始化

**死记一条规则**：

> **初始值 = "什么都没做" 时，这个状态应该等于多少**

按语义推（以 Armchairs 为例）：
- `dp[0][0]`：0 人放进 0 椅 = **0**（没事做，没成本）
- `dp[0][j]`：0 人放进 j 椅 = **0**（没人要放）
- `dp[i][0]`：i 人放进 0 椅 = **INF**（i > 0 时不可达）

按问题类型：

| 问题类型 | 合法空状态 | 不可达状态 |
|---|---|---|
| 求最小值 | 0 | +INF |
| 求最大值 | 0 | -INF |
| 计数 | 1（"什么都不做"算一种方案） | 0 |

## 关卡 3.5：防溢出（很重要）

**INT_MAX + 正数 = 负数**，会污染 min 操作。

求最小值时不要用 `INT_MAX`，改用：
```cpp
const int INF = 0x3f3f3f3f;  // ≈ 10^9，加几次都不溢出
memset(dp, 0x3f, sizeof(dp));  // 一行刷满 INF
```

求 long long 用 `0x3f3f3f3f3f3f3f3fLL` ≈ 4.6 × 10¹⁸。

## 五步流程（每道 DP 题严格按这个走）

1. **认出是 DP**（信号 + 贪心失败）
2. **选模板**（前缀 / 双序列 / 区间）
3. **写清楚 dp[...] 的语义**（一句话，能回答完整子问题）
4. **推转移**（最后一步有几种可能？各自从哪个子状态来？）
5. **补初始值**（"什么都没做"时每个维度该是多少；防溢出）
